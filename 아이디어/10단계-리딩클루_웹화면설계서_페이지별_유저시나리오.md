# PART 0 — 요약

## 0. 설계 원칙과 한 장 요약

### 0.1 5개 설계 원칙

```
원칙 1 — aicareerpath의 뼈대를 그대로 쓴다.
         5단계 여정 + 그룹 스페이스 + 탭 구조. 검증된 구조를 다시 만들지 않는다.

원칙 2 — 웹이 먼저다. 앱은 웹의 확장이다.
         모든 기능은 웹에서 완결되고, 앱은 알림과 빠른 작성만 더한다.

원칙 3 — 로그인 전에도 볼 것이 있어야 한다.
         공개 갤러리와 데모 진단은 로그인 없이 접근 가능하다.

원칙 4 — 독서 지도자는 3클릭 안에 그룹을 만든다.
         홈 → 그룹 만들기 → 완료. 그 사이 어떤 학습도 요구하지 않는다.

원칙 5 — 학생은 한 화면에서 이번 주 할 일을 안다.
         로그인 직후 "이번 주 미션"이 첫 화면 최상단에 있다.
```

## 3. 글로벌 네비게이션 설계

### 3.1 상단 GNB (데스크톱)

```
┌──────────────────────────────────────────────────────────────────────┐
│  📖 리딩클루   관심사 진단  책 탐색  독서 패스  독서 실행  About  [로그인] │

                                              ↑
                                    로그인 후 → [👤 내 프로필 ▼]
                                               ├ 내 기록
                                               ├ 포트폴리오
                                               ├ 내 그룹 (목록)
                                               ├ 설정
                                               └ 로그아웃
```

### 3.2 모바일 웹 하단 탭 (앱 전환 대비)

```
┌───────────────────────────────────────────┐
│                                           │
│              (콘텐츠 영역)                  │
│                                           │
├───────────────────────────────────────────┤
│  🏠     📖      ✏️      👥      👤        │
│  홈    로드맵   작성    그룹    내정보      │
└───────────────────────────────────────────┘
```

> 이 하단 탭 구조를 웹 모바일에서 먼저 쓰면, 앱 전환 시 그대로 재사용된다.

### 3.3 네비게이션 상태별 노출

| 상태 | GNB 노출 | 기본 진입 |
|---|---|---|
| **비로그인** | 진단 · 탐색 · About · 공개 아카이브 · [로그인] | `/` 랜딩 |
| **로그인 · 진단 전** | 전체 + [진단하기] 강조 배지 | `/quiz` 유도 |
| **로그인 · 그룹 없음** | 전체 + [그룹 참여하기] 강조 | `/groups/join` 유도 |
| **로그인 · 그룹 있음(멤버)** | 전체 + 내 그룹 바로가기 | `/groups/:id` |
| **로그인 · 지도자** | 전체 + [내 그룹 관리] | `/groups/:id` 대시보드 |

    Expo 앱 개발                :d1, 7, 2
    스토어 출시                 :d2, 9, 1

### 14.2 왜 웹 먼저인가

| 이유 | 설명 |
|---|---|
| **학교 환경** | 학교 PC·크롬북에서 즉시 사용. 앱 설치 불가한 환경 다수 |
| **초대 링크** | 카톡 링크 → 바로 열림. 앱은 설치 마찰 |
| **SEO** | 공개 아카이브가 검색에 노출 → 유입 채널 |
| **개발 속도** | 하나의 코드베이스로 데스크톱·모바일 모두 대응 |
| **심사 없음** | 스토어 심사 대기 없이 즉시 배포·수정 |

### 14.3 앱이 추가로 주는 것

| 기능 | 웹 | 앱 |
|---|:-:|:-:|
| 전체 기능 사용 | ✅ | ✅ |
| 푸시 알림 | △ (PWA) | ✅ |
| 오프라인 작성 | △ | ✅ |
| 사진 촬영 (책 표지·독서 노트) | △ | ✅ |
| 홈 화면 아이콘 | △ (PWA) | ✅ |
| 위젯 (이번 주 미션) | ❌ | ✅ |

### 14.4 웹→앱 코드 재사용 설계

```
공유 계층 (재사용 가능)
├── API 클라이언트         ← 100% 재사용
├── 타입 정의 (TypeScript) ← 100% 재사용
├── 비즈니스 로직          ← 100% 재사용
├── 상태 관리             ← 100% 재사용
└── 디자인 토큰 (색·간격)  ← 100% 재사용

플랫폼별 계층
├── 웹: Next.js + React    ← HTML/CSS
└── 앱: Expo + RN          ← RN 컴포넌트

→ 모바일 웹의 하단 탭 구조를 앱과 동일하게 설계하여
  UX 학습 비용 제로.
```
